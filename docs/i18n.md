# Internationalization

Fluid Chat ships with a small typed client-side i18n layer. The default preference is `system`,
which resolves the UI language from `navigator.languages` / `navigator.language` and falls back to
English when no supported language matches.

## Available languages

- `en` - English
- `fr` - French

## Add a language

1. Create a new locale file in `src/client/locales/<code>.ts`.

   Use `src/client/locales/en.ts` as the source shape and type the new export with `Messages`:

   ```ts
   import type { Messages } from "./en";

   export const de: Messages = {
     // Same keys as en.ts
   };
   ```

2. Register the language code in `src/client/i18n-core.ts`.

   ```ts
   export const SUPPORTED_LANGUAGES = ["en", "fr", "de"] as const;
   ```

3. Import and register the dictionary in `src/client/i18n.tsx`.

   ```ts
   import { de } from "./locales/de";

   const messages = { en, fr, de } satisfies Record<SupportedLanguage, Messages>;
   ```

4. Add the profile selector label in `LANGUAGE_LABELS` inside `src/client/i18n.tsx`.

   ```ts
   de: "Deutsch"
   ```

5. Allow the preference on the server and in shared typing.

   Update:

   - `src/db/schema.ts` (`UserPreferences.language`)
   - `src/server/routes/users.ts` (`preferencesSchema.language`)

6. Update documentation.

   Add the language to this file and to the global README.

7. Run validation.

   ```bash
   npm run typecheck
   npm test
   ```

The `Messages` type is derived from the English locale, so TypeScript reports missing or extra
translation keys when a new locale does not match the canonical structure.
